# 清史证据库 Phase 0 项目章程

版本：0.2.0（个人零预算版）  
工作方式：个人兴趣项目，AI 查证与编辑，不设置人工审核或付费前置条件
首个纵切片：康熙晚年—雍正初年的继承与皇族家庭

## 1. 项目使命

建立一套可复用的方法和底层模型，使清代人物的身份、称号、亲属关系、事件参与、画像认定和历史叙述，都能一键回到具体版本、卷页行、档号或图像区域，并能显式表达未知、冲突和后续修订。

当前优先级是内容精彩、前端展示逻辑好用、UI 漂亮、数据构建与运行稳定。日常流程保持简单：

```text
选题与资料 → AI 查证和编辑 → 页面展示 → 功能检查 → 持续改进
```

不要求用户逐条审核或外部专家签字。来源和争议按实际查证结果说明，不把复核数量、内容分级或资源大小变成发布审批。

## 2. 第一性问题

项目必须能可靠回答：

1. 某人到底是谁，有哪些异名和不同时期称号？
2. 两人是什么关系，这一关系在何时有效、依据是什么？
3. 某事发生在何时何地，当时参与者是什么身份？
4. 一句话来自哪一版玉牒、实录、档案、《清史稿》或现代研究？
5. 哪些内容已确认、推定、有争议、被否定或尚无材料？
6. 一幅画像是同时代原作、摹本、旧定名、后世想象还是 AI 生成？
7. 某资源允许本地保存、公开展示、商业使用，还是只能外链查阅？

## 3. Phase 0 范围

### 3.1 纳入范围

- 十二帝统一骨架，以及首批恰好 50 名康熙—雍正人物候选档；
- 以康熙、雍正及继承问题相关皇子、后妃、皇子配偶、外戚和关键大臣为中心；
- 玉牒/宗人府材料、《清实录》《清史稿》及精选宫中档、军机处档、国史馆材料的来源登记；
- 人物异名、亲属、婚姻、承嗣、册封、爵位、立储/废储、任官和事件模型；
- 画像和数字资产的对象化管理及逐件权利记录；
- 原图、忠实录文、标点文本、规范化文本、译释的分层设计；
- 十二帝基础权威档和《清史稿》《清实录》章节索引；
- 低保真页面规格：人物页、关系页、史料阅读器、图像页、争议事件页、编辑后台；
- 证据型检索与问答的接口约束，但不在 Phase 0 训练生产模型。

### 3.2 排除范围

- 全部宗室觉罗及在世后裔；
- 全量《清史稿》校勘或全量《清实录》入库；
- 大规模档案扫描、满文 HTR 训练、付费数据库和商业图片采购；
- 收费、商业授权和用户社区工程（研究稿站点已在 GitHub Pages 公开，属个人研究稿，不属此列）；
- 无证据的历史复原、动机推断和反事实故事。

## 4. 目标用户与默认任务

| 用户 | Phase 0 要验证的任务 | 默认输出 |
|---|---|---|
| 历史爱好者 | 快速理解人物、关系和事件，同时知道依据 | 通俗摘要＋证据抽屉 |
| 研究者/重度用户 | 核验异名、关系、卷页和版本差异 | 权威档＋原文定位＋冲突视图 |
| 编辑 | 从候选材料生产可发布知识单元 | 审核队列＋数据质量检查 |
| 教师/学生 | 比较不同史料如何描述同一事件 | 史料并排＋讨论问题 |

## 6. 零预算责任模型

- 用户：确定优先级、查看成果、对争议取舍做最终选择。
- AI：检索公开资料、建立结构化记录、生成候选主张、记录来源与版权、交叉核验、标出缺口并维护文件。
- 外部专家：不要求参与。AI 能查证的直接查证；暂时无法确认的具体问题说明不确定处，不挂起整个项目等待签字。
- 馆方或版权方：不是内容生产前置条件。没有明确许可的资源采用元数据与外链方案。

## 7. 决策原则

遇到冲突时依次遵循：

1. 可验证性高于叙事流畅度；
2. 权利清晰高于图片精美度；
3. 保留原始记录高于静默纠错；
4. 显示争议高于制造唯一答案；
5. 小范围高质量高于全范围低质量；
6. 可撤销的结构化数据高于不可维护的长文章；
7. 判断以实际资料为依据，不凭模型信心或审核身份作结论。

实体规则：皇帝首先是人物，帝号与在位是时态称号和事件。`QH-E-*` 不得作为第二套权威人物 ID；迁移时统一到 `QH-P-*`，避免玄烨、胤禛、弘历等重复实体。

## 8. 变更控制

方向性变化建议在 CHANGELOG 记一笔（日期、变化、理由），方便日后回溯；不记也不影响构建：

- 目标切片扩大到其他朝代或非皇室主题；
- 新增一种关系、证据或权利状态；
- 改变一个已发布人物的合并/拆分；
- 将黄色/红色来源改为本地公开保存；
- 更换公历换算算法或规范化规则；
- 采用会污染商业许可结构的外部数据集。

## 9. 预算原则

当前不设置内容采购预算：不要求用户为查看某份材料付费，不采购商业图片，不把服务器和正式网站作为启动条件。

**同时明确：公开可及路径不设人为上限。** 「需到馆」「需机构账号」「需数据库权限」不作为停止理由。遇到这类情况按以下顺序继续找路：

1. 已刊档案汇编（影印本、整理本、点校本）——这属于公开出版物，不是受限数据库；
2. 机构的公开在线检索目录与免费开放的档案影像；
3. 公共图书馆藏本、公共领域影印本、开放数据集；
4. 同版本替代或机构目录中的书目信息。

只有在上列路径全部走完仍无入口时，才登记缺口并保持「待核」——**并同时写明已尝试的路径**，使缺口可复算、可被他人接续。

## 10. Go / No-Go 验收

Phase-0 闭环验收（Go / Conditional Go / No-Go 全表）已完成使命，归档至 `docs/archive/01-phase0-acceptance.md`。

现行口径（开闸 v0.1 起，2026-09-11 进一步放开）：

- 技术检查：构建可运行、基础数据结构和页面功能正常；不设人工审核、章节成熟度、历法异常数量或资源体积门槛；
- 证据质量：看 STATUS.md 的采纳/审核中数字与抽查清单，只作参考，不设百分比指标，也不设上限/下限阈值；
- 仍然有效的红线：不编造来源、AI 内容与回查内容可分离、关键画像有权利链。
