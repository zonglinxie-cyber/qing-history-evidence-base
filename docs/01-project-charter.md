# 清史证据库 Phase 0 项目章程

版本：0.2.0（个人零预算版）  
工作方式：持续滚动生产，不设置付费前置条件  
首个纵切片：康熙晚年—雍正初年的继承与皇族家庭

## 1. 项目使命

建立一套可复用的方法和底层模型，使清代人物的身份、称号、亲属关系、事件参与、画像认定和历史叙述，都能一键回到具体版本、卷页行、档号或图像区域，并能显式表达未知、冲突和后续修订。

Phase 0 不证明我们已经“掌握清史”，只证明以下闭环可运行：

```text
资料发现 → 权利判断 → 编目/录文 → 实体消歧 → 主张提取
→ 证据核验 → 用户抽查／待专家复核 → 发布视图 → 纠错与版本化
```

## 2. 第一性问题

项目必须能可靠回答：

1. 某人到底是谁，有哪些异名和不同时期称号？
2. 两人是什么关系，这一关系在何时有效、依据是什么？
3. 某事发生在何时何地，当时参与者是什么身份？
4. 一句话来自哪一版玉牒、实录、档案、《清史稿》或现代研究？
5. 哪些内容已确认、推定、有争议、被否定或尚无材料？
6. 一幅画像是同时代原作、摹本、旧定名、后世想象还是 AI 生成？
7. 某资源允许本地保存、公开展示、商业使用，还是只能外链查阅？

## 3. Phase 0 范围

### 3.1 纳入范围

- 十二帝统一骨架，以及首批恰好 50 名康熙—雍正人物候选档；
- 以康熙、雍正及继承问题相关皇子、后妃、皇子配偶、外戚和关键大臣为中心；
- 玉牒/宗人府材料、《清实录》《清史稿》及精选宫中档、军机处档、国史馆材料的来源登记；
- 人物异名、亲属、婚姻、承嗣、册封、爵位、立储/废储、任官和事件模型；
- 画像和数字资产的对象化管理及逐件权利记录；
- 原图、忠实录文、标点文本、规范化文本、译释的分层设计；
- 十二帝基础权威档和《清史稿》《清实录》章节索引；
- 低保真页面规格：人物页、关系页、史料阅读器、图像页、争议事件页、编辑后台；
- 证据型检索与问答的接口约束，但不在 Phase 0 训练生产模型。

### 3.2 排除范围

- 全部宗室觉罗及在世后裔；
- 全量《清史稿》校勘或全量《清实录》入库；
- 大规模档案扫描、满文 HTR 训练、付费数据库和商业图片采购；
- 公开上线、收费、商业授权和用户社区；
- 无证据的历史复原、动机推断和反事实故事。

## 4. 目标用户与默认任务

| 用户 | Phase 0 要验证的任务 | 默认输出 |
|---|---|---|
| 历史爱好者 | 快速理解人物、关系和事件，同时知道依据 | 通俗摘要＋证据抽屉 |
| 研究者/重度用户 | 核验异名、关系、卷页和版本差异 | 权威档＋原文定位＋冲突视图 |
| 编辑 | 从候选材料生产可发布知识单元 | 审核队列＋数据质量检查 |
| 教师/学生 | 比较不同史料如何描述同一事件 | 史料并排＋讨论问题 |

## 5. 交付物和数量门槛

| 交付物 | 最低数量 | 完成标准 |
|---|---:|---|
| 十二帝基础档 | 12 | 每帝有规范名、庙号、年号、生卒、在位、父母、前后任、陵寝和史料入口 |
| 康熙—雍正候选人物档 | 50 | 每人有规范名、类型、异名候选、纳入理由、首要来源和待核问题 |
| 来源/版权台账 | 20 条 | 每条有访问方式、权利颜色、允许用途、核验日期和下一行动 |
| 已录入候选主张 | 200 | 主体、谓词、客体/值、时间、来源和状态齐全 |
| 人工核验主张 | 120 | 精确到卷页/档号/图像，含复核人和复核日期 |
| 关系主张 | 60 | 100% 有证据或明确标为待核/推定 |
| 称号/爵位任命 | 30 | 不使用静态最终头衔覆盖一生 |
| 关键事件 | 20 | 参与者身份和事件时间均可追溯 |
| 精校史料片段 | 30 | 原图/来源、忠实录文、校对状态和定位齐全 |
| 图像对象 | 20 | 作品性质、馆藏编号、人物认定和权利状态齐全 |
| 低保真页面规格 | 6 | 能覆盖人物、关系、史料、图像、争议、后台六种核心任务 |
| 黄金问题 | 60 | 覆盖事实查询、关系路径、版本冲突、无证据拒答 |

数量是下限，不是北极星指标。北极星指标为：

> **已完成来源回查且能精确回到证据位置的知识单元数。**

## 6. 零预算责任模型

- 用户：确定优先级、查看成果、对争议取舍做最终选择。
- AI：检索公开资料、建立结构化记录、生成候选主张、记录来源与版权、交叉核验、标出缺口并维护文件。
- 外部专家：不是启动前置条件。确有高风险学术判断时标记“待专家复核”，不能假冒已经复核。
- 馆方或版权方：不是内容生产前置条件。没有明确许可的资源采用元数据与外链方案。

## 7. 决策原则

遇到冲突时依次遵循：

1. 可验证性高于叙事流畅度；
2. 权利清晰高于图片精美度；
3. 保留原始记录高于静默纠错；
4. 显示争议高于制造唯一答案；
5. 小范围高质量高于全范围低质量；
6. 可撤销的结构化数据高于不可维护的长文章；
7. 人工审核结果高于模型置信度。

实体规则：皇帝首先是人物，帝号与在位是时态称号和事件。`QH-E-*` 不得作为第二套权威人物 ID；迁移时统一到 `QH-P-*`，避免玄烨、胤禛、弘历等重复实体。

## 8. 变更控制

任何下列变化必须进入决策日志，由用户确认；AI 负责记录影响和回滚方案：

- 目标切片扩大到其他朝代或非皇室主题；
- 新增一种关系、证据或权利状态；
- 改变一个已发布人物的合并/拆分；
- 将黄色/红色来源改为本地公开保存；
- 将 AI 候选绕过人工审核直接发布；
- 更换公历换算算法或规范化规则；
- 采用会污染商业许可结构的外部数据集。

变更记录至少保存：`decision_id`、日期、问题、选项、决策、理由、影响范围、批准人、回滚办法。

## 9. 预算原则

当前预算固定为 **0 元**。不购买数据库、不采购商业图片、不雇佣团队、不把服务器和正式网站作为启动条件。

若某材料必须付费才能查看，则登记书目信息和缺口，优先寻找公开的同版本、影印本、机构目录或其他独立材料；找不到就保持“待核”，而不是要求用户付费。

## 10. Go / No-Go 验收

### Go：同时满足

- 十二帝骨架恰好 12 条且继承链连续；
- 50 人候选样本无重复实体，关键异名可检索；
- 120 条来源回查主张中，100% 有精确来源定位；
- 60 条关系主张中，100% 能查看证据或明确显示未决状态；
- 同一人物的称号变化不被压成一个静态字段；
- 至少完成 3 组真实的冲突主张并排展示；
- 20 个图像对象权利状态完整，公开展示内容无红色资源；
- 黄金问题的结构化事实正确率 ≥95%，引文定位正确率 ≥98%；
- 系统面对无证据问题的正确拒答率 ≥95%；
- 数据模型未出现需要推倒核心表的阻断问题；
- 当前批次通过自动一致性检查，且用户确认继续扩展。

### Conditional Go：可修复后进入

- 一般字段或页面流程需要调整，但不影响证据模型；
- 黄色资源需要继续申请许可，但已有合法替代展示方案；
- 满文材料暂无法释读，但已明确标注缺口并不影响核心样本。

### No-Go：任一成立

- 关系边无法稳定绑定到证据；
- 人物合并、称号时间或版本差异无法表达；
- 依赖批量复制受限数据库才能继续；
- AI 生成内容无法与人工核验内容分离；
- 关键画像无法建立可靠的权利链；
- 把未经专家复核的高风险判断伪装成专家结论；
- 以“文章已经很多”替代质量验收。
