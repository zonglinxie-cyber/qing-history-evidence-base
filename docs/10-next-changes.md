## 任务 A｜图像重新分类（建议先做，是 B 的前提）

### 现状

`site/data/people.json` 的 `portraits` 有 **63 件**视觉材料，其中 55 件权利干净可嵌入。

现在按 `展示角色` 字段分类，只有 5 个值：

| 展示角色 | 件数 | 现在出现在哪 |
|---|---|---|
| 其他真迹 | 22 | **无任何页面** |
| 奏折朱批 | 16 | `#/hands` |
| 默认朝服像 | 12 | `#/images` |
| 御笔书法 | 10 | `#/hands` |
| 相关史迹 | 3 | **无任何页面** |

`handsPage()`（`site/app.js` 约 2197 行）硬编码只取 `奏折朱批` 与 `御笔书法`：

```js
const roles = [
  { role: '奏折朱批', title: '朱批与诏书', hint: '…' },
  { role: '御笔书法', title: '御笔', hint: '…' },
];
```

**结果：25 件（40%）任何浏览页都进不去**，其中 24 件权利是干净的。包括：

- **器物 6 件**：乾隆玉玺、道光龙袍、雍正珐琅彩孔雀纹碗、康熙官窑刻龙纹盘、同治官窑瓷、光绪龙凤双喜碗
- **便服／行乐／戎装／化身 13 件**：雍正道装像、雍正洋装猎虎图、乾隆佛装像、乾隆戎装骑马像、康熙南巡图卷七局部、道光园居像、咸丰读书像、同治写字像、康熙帝便服写字像等
- **历史照片 3 件**：光绪常服照、溥仪在紫禁城
- **史迹与后世画 3 件**

「其他真迹」是个 22 件的杂物筐——玉玺和行乐图混在同一个名字下。

### 目标

改用 `图像性质` 字段（数据里已有，35 种取值）重新归类成 **8 组**，让每一件都有归属和入口。

### 具体改法

**1. 在 `site/app.js` 增加归类函数**（建议放在 `MATERIAL_KINDS` 附近）：

```js
// 展示角色只有 5 个值，其中「其他真迹」是 22 件的杂物筐，
// 器物和行乐图混在一起，两个都露不出来。改用 图像性质 重新归类。
const VISUAL_GROUPS = [
  { key: 'court',   title: '朝服像',        test: /朝服像/ },
  { key: 'life',    title: '便服·行乐·戎装·化身',
    test: /便服|行乐|扮装|角色扮演|化身|戎装|骑马|狩猎|长卷/ },
  { key: 'brush',   title: '御笔',          test: /御笔|书法|匾额/ },
  { key: 'rescript',title: '朱批奏折',      test: /朱批|奏折/ },
  { key: 'edict',   title: '诏书上谕',      test: /上谕|诏书|官方文书|卷首谕旨/ },
  { key: 'object',  title: '器物',          test: /^器物$/ },
  { key: 'photo',   title: '历史照片',      test: /历史照片/ },
  { key: 'site',    title: '史迹与后世画',  test: /地景|后世历史画|史论/ },
];
function visualGroup(row) {
  const kind = String(row['图像性质'] || '');
  return VISUAL_GROUPS.find((g) => g.test.test(kind)) || null;
}
```

**归类顺序有讲究**：`edict` 必须排在 `rescript` 之前吗？不必——
但 `object` 用了 `^器物$` 精确匹配，必须保证不被 `life` 的宽松正则先吃掉，
所以 `life` 的正则里不能出现「器」字。按上面给的顺序和正则实测可以做到 **63/63 全部归类**。

自测方法：

```bash
node -e "
const fs=require('fs');
const P=JSON.parse(fs.readFileSync('site/data/people.json','utf8')).portraits||[];
// 把 VISUAL_GROUPS 抄进来跑一遍，确认未归类为 0
"
```

**2. 改写 `handsPage()`**

- 去掉 `roles` 硬编码，改为取**除 `朝服像` 外的全部 7 组**
- 无 `?era=` 参数时：**按组分段**（8 个 `h2`，含朝服像），组内按在位顺序排，每组标出件数
- 带 `?era=` 时：只取该朝，仍按组分段（该朝可能只有 2–3 组）
- 每个条目的角标（现在是 `.thread-year`）显示**组名**，不要再显示朝代
  （朝代已经由 `?era=` 或分组上下文给出）
- 页面标题改为「画的、写的、用的、拍下来的」，短名「像与物」（见第 3 点）

**3. 把 `#/images` 并进来，并改名为「像与物」**

不要保留「朝服像」单独一页。理由：不合并的话，`#/hands` 永远是一个
「除朝服像之外的其余」——**残余类目起不出好名字，也解释不清它为什么存在**。
合并后是完整的 63 件、8 组。`#/images` 保留为路由别名，旧链接不失效。

`MATERIAL_KINDS`（`site/app.js`）由四项减为三项：

```js
const MATERIAL_KINDS = [
  { key: 'works',   href: '#/works', title: '文献', hint: '实录、圣训、御制、敕编——这一朝写下的书和奉旨修成的书。' },
  { key: 'visuals', href: '#/hands', title: '像与物',
    hint: '朝服像、行乐图、御笔、朱批、诏书、器物、照片。书之外留下来的东西。' },
  { key: 'jiedu',   href: '#/jiedu', title: '逐解', hint: '原典拆成短引，每段配白话、「为何这样写」和「不能写成」。' },
];
```

**命名定稿**

| 位置 | 用词 |
|---|---|
| 材料卡短名 / `kicker` | **像与物** |
| 页面 `h1` | **画的、写的、用的、拍下来的** |

件数从 26 改为 **63**（其中可嵌入 55）。

为什么不再用「真迹」：它只覆盖手迹，盖不住龙袍、玉玺和照片；而且
「其他真迹」这个杂物筐正是这次要拆掉的东西，名字不该留着。
「像与物」对应三类内容——**像**（朝服、行乐、照片）、**笔**（御笔、朱批、诏书）、
**物**（器物）；`h1` 用四个动词把它们摊开，和站里「战场、陵寝、园子、关城」
是同一种写法。

**4. `reignMaterialBlock()` 的像与物计数**

现在用 `HAND_ROLES = new Set(['奏折朱批', '御笔书法'])` 统计，只算 26 件里的部分。
改为「该朝全部视觉材料」，朝代页右栏的数字才和 `#/hands?era=` 对得上。
**这一处不改会导致朝代页显示的件数少于点进去看到的件数。**

### 验收标准

- [ ] 63 件视觉材料，`visualGroup()` 全部命中，未归类为 0
- [ ] `#/hands` 能看到全部 6 件器物、13 件便服行乐、3 张历史照片

- [ ] `npm test` 全绿
