# 清史证据库 · 内容策略（Phase 0 配套）

版本：0.1.0
制定日期：2026-08-15
定位：给「清史证据库」项目设计一套零预算、证据派、可持续的内容生产—分发—沉淀体系
配套文档：`docs/01-project-charter.md`、`docs/05-six-week-execution-plan.md`、`README.md`

---

## 0. 一句话定位

> **清史证据库不是"更长的清史百科"，而是给清史爱好者的「证据派」资料库：我们不编故事，每一句话都让你看见出处。**

这是整个内容策略的灵魂，也是和市面上三类清史内容的根本差异：

| 市面主流 | 特点 | 我们的差异 |
|---|---|---|
| 清宫剧 / 影视二创 | 爽、戏剧化、混淆虚实 | 标注"此为后世想象"，回到原始纪年 |
| 野史营销号 | 标题党、单一故事线、不标来源 | 逐条回链卷页原文、敢标"有争议/待核" |
| 学术长文 | 严谨但门槛高、不与用户互动 | 同一证据给"发现/核验/教学"三档阅读深度 |

**结论：我们的"缺点"（不编故事、不追流量、敢标不确定）恰恰是内容钩子。** 内容策略的全部设计，都是把这个差异化放到最大。

---

## 1. 为什么现在需要内容策略

- 项目已有结构化证据底座（CSV 知识单元 + GitHub Pages 站点），但"酒香也怕巷子深"——没有对外内容，目标用户进不来。
- 当前清史内容生态存在一个**中间缺口**：想认真了解、但不满足于野史、又看不懂原文的人，找不到入口。
- 我们的证据模型（原子主张 + 证据抽屉 + 争议并存）天然适合做成"诱饵内容"，且内容生产可**直接复用六批次生产计划的产出**，边际成本极低。

---

## 2. 目标用户与内容诉求（分层）

内容必须同时服务四类人，但**触达顺序**应是"宽口进、深井留"：

| 层级 | 人群 | 他们在哪 | 内容诉求 | 留存动作 |
|---|---|---|---|---|
| L1 路人 | 影视剧考据党、清宫剧观众 | 小红书、抖音、B站 | "剧里演的对不对？" | 点进站点看证据 |
| L2 爱好者 | 清史爱好者、 genealogy 党 | 知乎、公众号、小红书 | 关系图谱、争议并存 | 收藏、追更 |
| L3 师生 | 历史教师、学生 | 知乎、公众号、B站 | 史料并排、可教学材料 | 引用、转投屏 |
| L4 研究者 | 清史研究生、重度用户 | GitHub、站点检索 | 卷页定位、版本差异 | 成为权威源、纠错共建 |

**策略重心**：用 L1 的"揭秘/还原"内容做触达，用 L2/L3 的深度内容做留存，用 L4 的严谨度做权威背书。

---

## 3. 内容支柱（5 根）

每根支柱都明确：**目标 / 示例选题 / 来源数据 / 适配平台**。

### P1 证据拆解（流量担当）
- **目标**：让分层看得见。钩子是「官书怎么写 / 通行说法差在哪」，不是揭秘结案。
- **示例选题**：
  - 《"九子夺嫡"是电视剧发明的词？实录里太子是怎么被废的》（锚定 `kangxi-heir-chain.csv`）
  - 《雍正继位"改诏说"站得住吗？看遗诏原文怎么写》（锚定 `yongzheng-source-units.csv`）
  - 《康熙"四后"：孝懿仁皇后生前竟不是皇后？》（锚定 `kangxi-empress-timeline.csv`）
- **来源数据**：`*-source-claims.csv`、`*-source-units.csv`、`side-lanes.csv`（传闻与官书分列）
- **适配平台**：小红书图文、B站短视频、知乎问答。

### P2 方法公开（信任担当）
- **目标**：展示"我们怎么把一句话连到卷页"，把 rigor 变成品牌资产。
- **示例选题**：
  - 《一张画像凭什么说是康熙？图像认定的 5 个证据层级》
  - 《为什么我们说"有争议"而不是给答案：争议并存的工程实现》
  - 《清史稿不是定论：我们怎么对待未定稿》
- **来源数据**：`docs/04-editorial-and-review-manual.md`、`emperor-portraits.csv`、`source-rights-ledger.csv`
- **适配平台**：公众号长文、B站幕后视频、GitHub 更新日志。

### P3 关系图谱（留存担当）
- **目标**：把"生母/嫡母/养母""继承链"等可检索关系做成 evergreen 内容。
- **示例选题**：
  - 《康熙 35 个儿子怎么排？一张表看清序齿与早殇》（锚定 `kangxi-princes.csv`）
  - 《雍正和十四阿哥到底是同母还是异母？看生母时间轴》
  - 《从努尔哈赤到溥仪：十二帝继承链为什么不断》
- **来源数据**：`kangxi-princes.csv`、`qing-emperors.csv`、`phase0-people.csv`
- **适配平台**：小红书长图、知乎专栏、站点关系浏览器截图。

### P4 史料通识（权威担当）
- **目标**：普及清史原始史料常识，建立"说到清史就想到我们"的心智。
- **示例选题**：
  - 《清实录 / 清史稿 / 玉牒 / 宫中档，到底都是啥？》
  - 《"年号纪年"怎么换算公历？为什么我们要保留原值》
  - 《军机处是怎么来的？一条关系边背后的制度》
- **来源数据**：`qing-emperor-source-index.csv`、`docs/03-source-and-rights-policy.md`
- **适配平台**：知乎、公众号、B站科普。

### P5 共建进度（留存+零预算杠杆）
- **目标**：把"生产进度、纠错公示、贡献指南"变成内容，撬动社区参与。
- **示例选题**：
  - 《本周新增 12 条可核验主张：我们在填哪些坑》
  - 《谢谢你纠错：上期 3 处讹误已修订并标注来源》
  - 《零基础也能帮我们：如何提交一条有效纠错》
- **来源数据**：`task-queue.csv`、`community-corrections.csv`、GitHub Issue 模板
- **适配平台**：站点公告、微博/动态、公众号月度通讯。

## 4. 平台与形式矩阵

| 平台 | 主力支柱 | 形式 | 频率 | 角色 |
|---|---|---|---|---|
| 小红书 | P1 / P3 | 图文卡（证据 vs 误解对比图）、关系长图 | 周更（≥1） | 触达 L1/L2 |
| 知乎 | P3 / P4 | 长文专栏、问答 | 双周（≥1） | 权威 + SEO |
| 公众号 | P2 / P4 / P5 | 深度长文、月度通讯 | 双周（≥1） | 留存 + 私域 |
| B站 / 视频号 | P1 / P2 | 屏幕录史料阅读器短视频（≤3min） | 双周（≥1） | 触达 + 方法展示 |
| 微博 / 动态 | P5 | 进度、金句、纠错公示 | 周更 | 活跃度 |
| **GitHub Pages / 站点** | 全部 | 权威落点（人物页/争议页/史料阅读器） | 随生产日更数据 | **一切内容的终点** |

**铁律**：每一条社媒内容必须回链到站点一个**具体页面**（人物页 / 争议事件页 / 史料阅读器），把流量沉淀为"查看依据"的动作。

## 5. 内容漏斗与闭环

```
        [ 社媒触达 ] 小红书/知乎/B站/公众号  ── P1/P3/P4 钩子内容
              │  回链到具体页面
              ▼
        [ 站点深度 ] 人物页/争议页/史料阅读器  ── "查看依据"证据抽屉
              │  发现问题 / 想参与
              ▼
        [ 贡献留存 ] Issue 纠错 / 贡献指南 / 月度通讯 ── P5
              │  正面体验
              ▼
        [ 口碑再传播 ] 用户自发引用、转发、二创  ── 回到社媒触达
```

闭环的关键在**第二层**：社媒负责"有意思"，站点负责"可核验"。没有站点兜底，流量就是一次性烟花。

## 7. 生产工作流（贴合项目章程）

```
AI 生成候选（录文/实体/主张/叙事草稿）
   │  标注状态：审核中 / 待核 / 有争议
   ▼
人工复核（证据精确定位 + 权利颜色判断 + 冲突并存）
   │  未经人工复核，AI 内容不得发布（章程原则 5、7）
   ▼
发布（社媒 + 回链站点具体页面）
   │
   ▼
用户纠错（GitHub Issue 模板：内容纠错 / 图像与权利 / 站点 Bug）
   │
   ▼
回到生产队列（task-queue.csv）修订并版本化
```

**红线（不可为流量突破）**：
- 不把野史包装成"另一种同等可能的历史"；
- 黄色/红色资源只给元数据 + 馆藏外链，绝不伪装成可下载资产；
- AI 生成图始终标注"现代想象 / 非历史原像"；
- 可验证性 > 叙事流畅度（章程决策原则第 1 条）。

## 8. 治理与边界（不越 Phase 0 红线）

`docs/01-project-charter.md` 第 3.2 节将"公开上线、收费、商业授权和用户社区"列入 **Phase 0 排除范围**。因此：

- **内容可先行**：对外科普、引流、纠错收集都不越界，属于"证据生产"的副产品；
- **正式社区功能留待 Phase 1**：账号矩阵、互动、贡献者体系先做轻量版，不投入社区工程；
- **零预算硬约束**：不买量、不采商业图、不付费授权；发现材料需付费则登记缺口、标"待核"，绝不要求用户花钱；
- ** authorship 透明**：所有引用标注来源与权利颜色，CC BY 4.0 内容允许二次传播并署名。

## 9. 指标

**北极星指标（一条）**：
> 经内容进入站点、并至少触发 1 次"查看依据"（打开证据抽屉 / 点击关系边 / 复制引文）的用户数。
> 它同时衡量"触达质量"和"证据价值兑现"，比阅读量更贴近项目使命。

**过程指标（周/月看板）**：

| 指标 | 含义 | 健康线（建议） |
|---|---|---|
| 社媒阅读 / 互动 | 触达广度 | 逐月稳中有升 |
| 回链点击率 | 内容→站点转化 | ≥ 社媒流量的 8% |
| 站点"查看依据"触发 | 北极星过程量 | 随内容周环比增长 |
| 纠错 / Issue 提交 | 社区参与（零预算杠杆） | 每月 ≥ 3 条有效纠错 |
| 关注 / 订阅净增 | 留存 | 逐月正增长 |

## 10. 90 天落地清单

### 必须（不花钱、本周可启动）
- [ ] 定位语定稿（第 0 节一句话），全平台简介统一；
- [ ] 开通并装修账号矩阵：小红书、知乎、公众号、B站、微博（简介均回链 GitHub Pages）；
- [ ] 用 W1–W4 选题产出首批 4 篇内容，全部回链站点具体页面；
- [ ] 固化编辑日历（本表），生产排期与六批次对齐；
- [ ] 建立"发布前核对清单"：证据定位✓ / 权利颜色✓ / 回链✓ / AI未越权✓。

### 可选增强（按精力推进，不制造"还得继续"的压力）
- [ ] 视频化：把史料阅读器做成 ≤3min 短视频系列；
- [ ] 纠错激励：非金钱的"贡献者署名页"；
- [ ] SEO 长尾：知乎/公众号做"清史稿是什么"等搜索词占位；
- [ ] 多朝代预热：在站点和内容里埋"下一代朝代"钩子，为 Phase 1 铺路；
- [ ] 数据看板：用 `golden-questions.csv` 反推"用户最常搜的误解"作为选题库。
