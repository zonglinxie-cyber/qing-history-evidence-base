# 编辑与审核手册

当前用途：数据字段与查证方法参考，不是审批清单。个人兴趣项目由 AI 查证和编辑，不要求用户逐条审核或专家签字。已有复核记录可保留，但记录数量、章节成熟度和日期检查结果不决定能否构建、浏览或发布；实际优先级见 [项目章程](01-project-charter.md)。

## 1. 发布对象不是“句子”，而是可审计主张

主张最小结构：

```text
主体 + 谓词 + 客体/字面值 + 有效时间
+ 来源定位 + 证据类型 + 状态 + 审核记录
```

叙事文章按「先发后标」可引用任意状态的主张 ID，但每个被引主张都要带状态徽标（审核中／待核／有争议／已采纳）；编辑采纳不得单独作为定论依据，应按来源性质与复核范围表述。底层主张发生变化时，系统必须标记受影响文章。

正文插图用整行语法 `{{fig:QH-V-E04}}`，可写作 `{{fig:QH-V-E04|自定义图注}}`。权利检查在构建期完成：仅绿色且可公开展示的图像嵌入，黄色/红色自动降级为「说明＋外链」，引用不存在的图像 ID 会在构建时告警。插图不得改变主张的证据层级——图是呈现，不是来源。

## 2. 工作状态与复核

编辑状态、字段登记和来源对照分开记录。

- `状态` 保留编辑决定；旧 `已采纳` 可能来自历史自审，不代表已经人工或逐条核验。
- `npm run self-review` 只读检查，不改变 CSV，不自动采纳，也不恢复已驳回/已废弃记录。
- `data/claim-review-baseline.json` 只存修复时的证据指纹，用来发现主张、来源单元和来源台账变化；不是核验凭据，不应为清除提示随手刷新。
- `data/review-records.json` 按主张 ID 记录实际录文对照。记录须包含 `fingerprint`、`result: "录文已对照"`、`reviewer`、`checkedAt`（YYYY-MM-DD）、`note`（对照的版本与位置、方法和限制）。指纹由 self-review 同一模块计算；必须在真正对照后填写，不能把运行脚本当完成核验。
- 记录指纹不再匹配当前主张、来源单元或台账时，显示“需复核”，不继续计入录文已对照。
- 依据抽屉和主张卡显示“引文已登记／录文已对照／需复核／已驳回／已废弃”；冲突组另外显示。录文已对照也只证明所引文字与所查底本一致，不证明事件为真。

整站保持 `noindex`。`chapters.csv` 的“收录”只作内部推荐目录标记，不决定搜索引擎收录。

## 3. 人物权威档规则

### 3.1 名称不混写

分别记录：

- 本名、幼名；
- 满文/蒙古文等原文和转写；
- 汉字异写；
- 避讳前后写法；
- 庙号；
- 谥号及完整谥号；
- 尊号；
- 爵号；
- 年号；
- 现代常用称呼和外文旧拼法。

“康熙”“雍正”首先是年号；“圣祖”“世宗”是庙号；不得全部塞进一个 `name` 字段。

### 3.2 合并与拆分

- 同名不自动合并；
- 异名候选至少由两个特征支持，如亲属、旗籍、时间、职官、来源明示；
- 合并必须可撤销，并保存原记录 ID；
- 影响多条主张的合并，由 AI 核对关联和页面结果，不要求第二位编辑签字；
- 外部权威库只作对齐，不自动覆盖本库判断。

## 4. 关系规则

必须区分：

- 生父、生母；
- 嫡母、继母、养母、乳母、抚养者；
- 亲生子女、嗣子女、过继入、过继出；
- 配偶、正妻、侧室、订婚、追认婚姻；
- 同父、同母、同父同母手足；
- 宗支和房次；
- 爵位承袭；
- 师徒、姻亲、举主、门生、同年；
- 政治合作、弹劾、案件对立和派系归属。

“兄弟”关系优先由共同亲本动态推导；若史源直接使用该称谓，可另建来源明确的主张。

任何关系边都必须回答：

1. 关系属于生物、法律、礼制、婚姻、社会还是政治？
2. 何时有效？
3. 谁这样记载？
4. 原文在哪里？
5. 是否有冲突材料？

## 5. 称号、爵位和职官

人物表中不保存一个覆盖一生的最终称号。每次变化建独立任命/授予记录：

- 开始和结束时间；
- 原始称谓；
- 授予、追封、降位、复位、革爵、署理、兼任；
- 册文、诏书、实录或档案依据；
- 是否在死后发生。

页面按用户选择的日期计算当时称号。

## 6. 事件边界

事件至少记录：

- 事件类型；
- 原始名称和编辑标题；
- 时间范围及精度；
- 地点；
- 参与者、当时身份和角色；
- 直接证据；
- 后来记述；
- 事件边界为何这样划定；
- 对称号、关系、任官和后续事件的影响。

不得用“九子夺嫡”这类后世概括代替一系列具体事件。

## 7. 文献录文规则

### 层级

1. 机器 OCR/HTR；
2. 校对过的忠实录文；
3. 精校录文（单人项目用「隔轮重校」替代双人校对：放一轮再回头逐字核对）；
4. 标点；
5. 规范化；
6. 译释。

### 要求

- 录文逐页/逐图绑定原图或馆藏定位；
- 版面顺序、双行小字、朱批、印章、夹签等单独标记；
- 缺字、疑字、补字均有符号和责任者；
- 标点不能写回忠实录文；
- 繁简转换和避讳字还原均为派生层；
- 关键片段隔轮重校后再标精校；
- 满文、蒙古文、藏文未经专项审核不得标为已精校。

## 8. 证据状态与争议

推荐状态：

- `confirmed`：直接且一致的高质量证据；
- `corroborated`：多个独立来源支持；
- `probable`：证据较强但仍有推断；
- `disputed`：存在合理互斥说法；
- `unresolved`：材料不足，暂不判断；
- `rejected`：证据不足或已被可靠材料否定。

不得把状态折算成一个看似科学的全局分数。数值置信度只供排序，公开页面必须有文字解释。

争议记录建立 `conflict_group`，并列：

- 互斥主张；
- 各自主张者/史源；
- 支持和反对证据；
- 编辑判断；
- 判断的适用范围和保留意见。

## 9. 图像审核

图像发布前完成两次独立检查：

### 内容检查

- 画中人物是谁，依据是什么；
- 旧定名还是当前定名；
- 作者/年代是否只是传称；
- 是否生前写真；
- 是否为局部、摹本、复制或后世再创作；
- 服饰和场景是否支持人物/年代判断。

### 权利检查

- 数字图像许可；
- 权利人和馆藏机构；
- 允许用途；
- 必要署名；
- 是否允许裁切、修改、商用、模型训练；
- 许可页面快照和核验日期。

## 10. AI 使用边界

### 允许

- OCR/HTR 候选；
- 实体和异名候选；
- 主张候选；
- 相关史料召回；
- 冲突检测；
- 已审核主张上的摘要草稿；
- 格式转换和质量检查。

### 禁止直接发布

- 模型猜补的残字；
- 无直接证据的亲属、死因和动机；
- 自动合并的人物；
- 自动换算但未记录方法的日期；
- 无卷页定位的引文；
- 把“未找到”改写为“没有”；
- 把艺术生成图当历史画像；
- 只基于向量相似度生成的家谱或事件链。

批量机器加工在提交信息或编辑备注里留一句说明（做了什么、依据哪条来源）即可，不做逐条哈希级留痕；git 历史承担修改记录。

## 11. 建议复核清单

下列内容由只读检查列出登记与变化情况（`npm run self-review`），仍需实际对照来源，进入「建议顺手抽查」清单而非发布门槛；实际有专家参与时再升级为专家复核。本节是工作提示，不是拦截规则：

- 生母、嫡母、养母、承嗣和过继；
- 立储、废储、遗诏、即位合法性；
- 死因、疾病和秘密政治活动；
- 画像人物或作者重新认定；
- 人物合并/拆分；
- 传统纪年与公历转换有争议；
- 引用受限档案或现代点校成果；
- 会改变 3 个以上页面的主张。

## 13. 叙事文风建议（防 AI 填充腔）

正文建议只保留可信、可验证的叙事；只为“语感”存在的句子，用具体年份、卷次、姓名或冲突组代替。

### 13.1 章节结构

每篇章节按深度选用下列层次，避免用背景注水或动机心理描写填充：

1. **先说结论**：直接给结论，句句落到具体年份、卷次、姓名或冲突组；
2. **怎么读**（深挖章）：解释术语、史料分层或冲突组怎么读；必须落到卷次、ID 或冲突组，不能写制度史空评；
3. **分日讲解 / 骨架**：每天或每条一句事实 + 一句状态（待核／冲突组／已回原文）；讲解只解释已打开材料，不补未回原文的情节；
4. **边界 / 尚未解决**：进入可折叠的证据抽屉（构建期自动处理），不占正文叙事。

索引级章节可以只有「结论 + 骨架 + 边界」。深挖样板章（如两废太子、即位与遗诏、雍正即位）应有「怎么读」和分日讲解，骨架可并入分日，不必重复罗列。

研究元信息（范围、边界、尚未解决、待抽查、CSV 路径、任务 ID）只保留在研究稿与结构化数据里，不得写进正文叙事层。

### 13.2 禁用清单（AI 填充腔）

以下词语和句式建议避免（写作参考，不再由构建强制校验）：

- 空洞结论：`深远影响`、`最重大的变革/事件`、`极为罕见`、`绝无仅有`、`独树一帜`、`引人注目`；
- 空洞比较与心理描写：`心理冲击`、`评价两极`、`显著分歧`、`高度一致`、`紧密咬合`；
- 视角套话：`在更宽广的视野中`、`进一步分析`、`特别值得注意`、`值得深思`；
- 三连枚举注水：用 `(a)(b)(c)` 罗列“分析”却没有对应史实或材料；
- 单标签概括：`盛世`、`衰世`、`反腐`、`傀儡`、`平庸`，除非它本身是史料用语或被明确标注为后人评价。

判据：**删掉这句后，损失的不是史实、日期、人名、数字、卷页或引文，而是“语感”，就删。**（对应章程决策原则 1：可验证性高于叙事流畅度。）

### 13.3 允许保留的克制句式

以下是本库的“证据克制腔”，不是 AI 套话，应保留：

- `不能把 X 写成 Y`、`本库不取总数`、`两说并存，不择一抹平`；
- `未回原文`、`待核`、`只登记入口`、`未见`、`本条未拆`；
- 冲突组编号 `QH-CF-*`、回查状态 `E1 / S / C`、史料性质分级（`同时代·官方` / `同时代·私撰` / `后出`）等。

### 13.4 落点

- 新章节想自查时按 13.2 过一遍；默认构建不做文风校验，只有 `npm run validate:strict` 才会对 `## 骨架`、`## 怎么读这件事`、`## 分日讲解`、`#### 读这一句` 里带评述句式、又无卷页/ID/引文锚点、也无克制语的句子发提示；
- 已有索引级章节若含“背景扩充段”，先删背景段、再补具体事实；
- 构建脚本已把「范围 / 边界 / 尚未解决」折叠进证据抽屉，正文应只剩结论、怎么读与分日/骨架。

### 13.5 性格、功过、「读这一句」

- **性格**只写见诸文书、可系年月日的行政习惯（用人节奏、责让、自述）。禁止心理传记、影视人设、单标签。幼帝此栏改名「决策空间」。
- **功过**不用功/过二字。三拍：当时要解决什么 / 做了什么 / 留下什么。后人评价单独标后出。
- **读这一句**五栏：原文（与主张引文一致）/ 今译 / 当时语境 / 今天还读（只落阅读技能）/ 不能写成。一张卡只绑一条已入库主张。今译不补动机、路程、钟点、诊断。

### 13.6 重点文章的呈现层次（夜改 2026-09-19 闭环 B 起）

来自《大义觉迷录》分层与《乾隆身后十五日》精修两篇的做法，适用于首页精选指向的长章：

- **三十秒定位。** 正文第一节就给「这篇回答什么问题 + 依据哪几件记录 + 各能走到哪一步」，可用一张三列表（问题 / 记录 / 走到哪一步）。研究性元信息（来源家族、后出与同时代分级、未见何档）留在「范围」抽屉，不占正文开头。
- **原句进正文。** 决定这一节结论的那句原文（本纪分日句、上谕第一句、宫规一句）出现在正文或表格里，不能只在角标点开「依据」后才看见。
- **模板标签按内容出现。** 「原文—白话—为何这样写—今天怎么读」四类标签不逐段套；白话与原文同义反复时删白话，限制说明改写成紧邻论述的一句。五栏只用于 `#### 读这一句`（见 13.5）。
- **判断要带论证。** 不写「最诚实」「最漂亮」「谁控制什么谁就赢」一类可套到任何章上的句子；文本层面的可能性不写成心理活动，也不写成历史定论（「和珅是否另有打算」这类问题应写明明说没有材料回答）。背景性事实（谁弹劾、何时会鞫）也要落到卷次或主张 ID。
- **缺口写成缺口。** 缺证据处写「缺口／本次未见」，并说明需要哪一类材料（该月实录日页、抄家清单原档、审讯题本、影印本对校），不得补造引文、卷页、档号、日期。
- **编辑流程提醒不入正文。** 干支异文的校改流程归 `docs/22-CAL-001核录工单.md`，冲突组登记归 `docs/23-冲突组学术史登记说明.md`，版本质量（如维基文库 Textquality 50%）与来源单元登记归 `data/source-units.csv`；正文只留与理解直接相关的来源限制。这几项在源文件里可继续挂在 `## 边界`（构建期不进公开正文）。
