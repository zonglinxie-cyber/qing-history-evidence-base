# 历日与满汉纪年（怎么用、缺什么）

> 权威登记：`data/calendar-baseline.csv`。工单与机器校验：`docs/22`、`data/calendar-audit.csv`、`data/calendar-worksheet.csv`。  
> 规范：`docs/03` §7。后两张日历表是内部工作表，不进站点、不进 manifest。

---

## 一、四条基准

| ID | 名称 | 状态 | 读者层怎么写 |
|---|---|---|---|
| CAL-001 | 陈垣《二十史朔闰表》 | 本库**唯一**换算基准；机器自洽已跑；具书核录 0／892 | 写书名，不写「CAL-001」 |
| CAL-002 | 郑鹤声《近世中西史日对照表》 | 抽校用，待具备 | 与 CAL-001 不一致时两说并存 |
| CAL-003 | 清代时宪历月首与闰月 | **来源未定** | 无此数据，不得声称月日已精确对照朔闰 |
| CAL-004 | 「通行年表」泛指 | **已作废** | 禁止再写「依通行年表」 |

结构化数据（主张的编辑备注）可以写 CAL-001；面向读者的章节写「依陈垣《二十史朔闰表》」。

## 二、日常怎么用

1. 原始年号纪年原样保存，不改写成公历再覆盖回去。  
2. 公历上下界与确定性并列。日级对照在具书核录前维持现值，标约略或在备注写「尚未逐条核录」。  
3. 跨年陷阱必须写明：例如康熙十四年十二月属公历 1676 年 1 月，年号纪年仍是十四年。`docs/22` 的 C7 会提示这类条。  
4. 复跑：`npm run check:calendar`。机器通过 ≠ 与陈垣书页一致。  
5. 发现干支或换算不对：`npm run errata`（例：ERR-001 挂在嘉庆元年正月朔）。

现库硬矛盾仍是嘉庆元年正月朔：同一公历日 1796-02-09，卷 15 戊申、卷 16 戊辰。冲突组 `QH-CF-QL-JQ-ABDICATION-GANZHI`。有两条主张引用了争议表达却未挂组 ID（`docs/23` §4），皇帝代理补挂即可，不要先择一。

## 三、缺什么（满汉纪年）

| 缺 | 含义 |
|---|---|
| 具书核录 | 423 个唯一时间表达尚未对书页 |
| 朔日与闰月 | 需要 CAL-003，来源未定 |
| 满文纪年字段 | 人物档有「满文名」类型，时间表没有满文月日／穆克敦等专名栏 |
| 时宪历与西洋历并书 | 康熙历狱、南怀仁等在专章，未接入 calendar 表 |
| 宣统／民国／伪满纪年混用 | 溥仪 1912 后退位；`QH-V-E12D` 用康德十年，必须与宣统纪年分栏 |

本页不提供换算表，也不手算朔闰。需要日级结论时，先走工单，再回专章。
